## 二、交付物与放置

**交付物**：`license.key` 单行 JWT（RS256，header `{"alg":"RS256","kid":"key_v1","typ":"JWT"}`）。

**交付方式（2026-10-19 修订，第二次交付）**：**受控文件通道**——明文由平台侧从 `license_tickets` 原文写出到 CVM：

```
/root/.license-delivery/ecms-xgn-LIC-202610-QMOT.key    # 1312 bytes, mode 600, dir 700
```

接收方校验 `sha256sum` 与 `wc -c` 一致后 `install -m 600 -o root -g root` 到目标路径，随后删除交付文件。

**本仓不落明文**，只记 sha256 与工单号。

> ⚠️ 事故记录（当天两次）：①首版只发了 sha256，未交付明文 → 申请方无法安装；②第二版经聊天通道直贴长 base64，被整体替换（段1 首字节 `7b 22 61`→`7b 25 31`），长度仍 1312，sha256 不符 → 接收方 NACK 拒装，未写入、未 restart。已据此在规则 v1.3 中禁止文本直贴长凭据，改为文件通道 + 双端 sha256 交叉校验。

**放置**：`/var/www/xgn/ecms-backend/license/license.key`，权限 `600`、owner `root`。

⚠️ **sha256 校验提醒**：回执 sha256 基于 token 本体（1312 字符，无换行）。若写入文件时末尾带换行，`sha256sum license.key` 会不一致——请按 `printf '%s' "$KEY" > license.key` 或先 `tr -d '\n'` 再比对。ECMS 读取时已 `.strip()`，功能上不受影响，但验收第 4 项会对不上。

`public.pem` 沿用既有共用那份，**无需重发**；未提供任何私钥。

## 四、`domain` 的生效条件与已知限制（**请务必转达实施与运维**）

1. **生效前提**：xgn 实例的 systemd unit 必须设 `Environment=INSTANCE_DOMAIN=yzxgn.ecms.ziwi.cn`——**精确值，不带 `https://`、不带端口、不带路径、不带末尾点、大小写一致**。`verify.py` 是字符串精确比较，任一处不符即 `DOMAIN_MISMATCH`。
2. **当前仍是软模式**：`LICENSE_HARD_ENFORCE` 未开启 → 即便 domain 不符，也只 `valid=false` + 一条 warning，业务照跑。**本次是"把字段埋进去"，不等于已形成访问控制**，请勿据此对外宣称"已完成域名绑定防护"。
3. **换域名必须重签**：证绑定了具体域名，客户一旦改域名/换备案，旧证即失效。届时需重新签发。
4. ⚠️ **续期陷阱（平台侧已知缺口）**：`license_tickets` 表**没有 `domain` 列**，该 claim 只存在于证内（本次由一次性脚本写入）。若将来在 cloud 后台点「重新签发」，走 `issue_license_key` 的固定 8 项 claims，**新证会静默丢掉 `domain`**，且不报错。**因此 xgn 续期必须走人工重签（同本次做法），不得走 UI 一键签发。** 已在 STATUS 台账标注。
5. **公网暴露面（已核实，无需处理）**：vhost root 为 `/var/www/xgn/ecms`，key 在 `ecms-backend/license/` 下、**不在 web root 内**。WorkBuddy 2026-10-19 实测 `https://yzxgn.ecms.ziwi.cn/license/license.key` 返回 200 但为 446B 的 SPA 兜底页（与根路径同尺寸），取不到真文件 → 不另行加 nginx deny。
6. ⚠️ **`iat` 位于未来的兼容风险（PyJWT 版本相关）**：`iat=1792425600`（2026-10-20 00:00 CST）在起算日之前属未来时间。当前实例 PyJWT **2.3.0 只校验 `iat` 为整数、不校验未来值**，故起算日之前安装即可通过；但 **PyJWT ≥ 2.10 会校验未来 `iat` 并抛 `ImmatureSignatureError`（表现为 `INVALID_SIGNATURE: The token is not yet valid (iat)`）**。请将"升级 PyJWT 前先确认已过 2026-10-20 00:00 CST"写入 ECMS 升级检查清单。
7. **systemd 现状（2026-10-19 实测）：无需改 unit**。`xgn-ecms-backend.service` 已含 `Environment=LICENSE_DIR=/var/www/xgn/ecms-backend/license` 与 `Environment=INSTANCE_DOMAIN=yzxgn.ecms.ziwi.cn`（值精确），且无 `*.service.d/` drop-in 覆盖。装证后**仅需 restart**，不必 `daemon-reload`。
