> 制定方：codebuddy（cloud IdP / License 发放 / 心跳线）
> 生效日期：2026-10-19（即日执行）
> 修订：**v1.1（2026-10-19）** 补 R4「交付闭环」+ 新增 R11「事实以服务器为准」，来源：xgn 首次签发时"签发完成但申请方拿不到明文"的空转事故
> 修订：**v1.2（2026-10-19）** 新增 §6「受理方铁律（codebuddy 自约束）」+ 回执模板，把上述教训固化为我方每次回复的强制结构
> 适用范围：school / mfg / ecms 三条产品线的 **License 申请、签发、交付、安装、验收、续期、失效处理**
> 权威源：本文件 + `STATUS.md`。License 相关事项与其他文档冲突时，以本文件为准。
> 异议窗口：如对某条有异议，在 `STATUS.md` 开一节写明"条款 + 事实 + 替代方案"，**不得单方面不执行**。

---

## 0. 为什么定这份规则

License 是**跨团队凭据**，不是某一方的本地配置。2026-10-19 的 ecms-xgn 已暴露三类问题：

1. **口径不清**：`deploy_mode=private` 被理解成"客户机房"，实际是"我方 CVM 上的独立实例"；
2. **通道不清**：`license.key` 明文到底走 Git 还是私发，没有约定；
3. **机制不清**：`domain` 这类新 claim 不在工单表里，**续期一键重签会静默丢掉**，且无人会察觉。

三者都会变成生产风险，因此固化入口、字段、交付、台账与续期。

## 1. 十条规则

### R1 单一入口：License 事项只走协同仓 `requests/`

- 一律按模板 `requests/_模板-License申请.md` 提交，文件名 `{tenant_id}接入申请-License-{YYYYMMDD}.md`。
- **不接受**IM 对话、口头、截图、代码注释作为申请依据。
- 平台只在协同仓受理，并在同一目录出回执；回执未出＝未签发。

### R2 申请必备字段：缺"阻塞项"即退回

| 类别 | 字段 | 阻塞? |
|---|---|---|
| 租户 | `tenant_id`、`tenant_name`（写法统一：`公司名 \| 系统标题`） | ✅ |
| 授权 | `product`、`tier`、`seats`、`deploy_mode`、有效期起止（CST，精确到日） | ✅ |
| 绑定 | 是否要 `domain`，及**精确域名** | ✅（要的话） |
| 实例 | 实例域名、部署位置（CVM 目录 / 客户机房）、负责人 | ✅ |
| 运行 | 硬模式还是软模式、是否接心跳 | ✅ |
| 商务 | 合同起止、席位数、模块清单 | ❌ 非阻塞（可标"待回传"） |

**`deploy_mode` 定义（必须按此填）**：

- `private` = 一客户一独立实例（独立目录 + 独立库），**可托管于我方 CVM**；这是 ECMS 线现行口径。
- 若部署在**客户机房**，申请中必须额外注明"onprem"及交付方式，不得只写 `private` 混同。
- `saas` = 共享实例，走身份（JWT）链路，通常不发离线证。

### R3 claim 白名单：新增字段必须先申请、由平台决定是否落库

当前白名单（共 12 项）：

```
license_id, ticket_no, tenant_id, tenant_name, products,
tier, seats, deploy_mode, domain, typ, iss, iat, exp
```

- 新增 claim 须在申请中单列：**字段名 / 取值 / 消费方代码位置 / 缺失时的降级行为**。
- 平台若判定"暂不落库"，只能**一次性人工签发**，且须在回执中明示：
  **「该字段不在工单表内，续期重签不会自动延续」**。
- `modules` / `max_devices` 未进白名单前，一律不写。写入未约定字段会让后续读成"已授权范围"。

### R4 交付与保管：明文只走线下，Git 只记 sha256

| 项 | 规则 |
|---|---|
| 明文 `license.key` | **不入 Git、不入文档、不入工单备注**；由主理人渠道点到点私发 |
| Git / 回执 | 只记 `ticket_no`、`license_id`、`iat/exp`、`sha256`、字符长度 |
| sha256 口径 | 基于 token 本体（无换行）。写文件必须 `printf '%s'`，末尾不得带换行 |
| 文件权限 | `chown root:root` + `chmod 600` |
| 目录暴露 | 必须确认该目录不在任何 vhost 的 `root` 内；建议 `location ~* /license/ { deny all; }` |
| 严禁 | ①复制其他租户的证；②在代码里硬编码"借证兜底"（如已删除的 dna 目录 fallback）；③改任何 claim 值（改动即签名失效）；④转发给第三方 |

**R4 补充 · 交付闭环（v1.1 新增，强制）**

- 签发完成后 **同一工作日内**，受理方必须把**明文**交给申请中填写的「验收人」，并在回执记：`已送达：时间 / 渠道 / 接收人`。
- 接收人 **2 小时内回 ack**（"已收到，长度 N，sha256 前 8 位 X"）。
- **未 ack = 未送达 = 本次签发未完成**，不得计入"已发放"。
- 允许渠道（按优先级）：①同一会话直接贴；②主理人点对点转发；③本地临时文件（不入仓）。**禁止**：Git、工单备注、群公告、日志、截图二维码。
- 事故来源：v1.0 只写"禁止入 Git"，未写"谁在何时把明文送到"，导致 2026-10-19 xgn 签发完成、申请方数小时拿不到 key，全部动作停在"准备工作"。

### R5 实例台账：接入方登记，平台核对

每条 License 必须在 `STATUS.md`「实例台账」登记，**新实例 24 小时内补齐**：

| tenant_id | 域名 | 部署位置 | 负责人 | 部署日 | 到期 | 硬/软 | 心跳 | 证 sha256 | 最后验证日 |

- 台账由**接入方**维护，平台每季度核对一次；
- 台账与云平台 `license_tickets` 不一致时，以平台为准，接入方 3 工作日内更正。

### R6 续期：提前 60 天，含 domain 的证必须人工重签

- **到期前 60 天**由接入方发起续期申请（同 R1 模板）；平台不主动延期，也不自动扣费续签。
- 平台 `issue_license_key` 目前固定 8 项 claims，**不含 `domain`**。因此在"domain 落库"改造完成前：
  - **含 `domain` 的证，续期一律人工重签**（同 2026-10-19 xgn 做法），
  - **禁止**在 cloud 后台点「一键签发/重签」——会静默丢掉 domain 且不报错。
- 续期完成后，接入方须回传新证 `sha256` 与新有效期；旧证同期作废。

### R7 失效与模式：硬模式须双方书面确认

- 到期/吊销**不自动降级**。软模式下只置 `valid=false` + 日志；业务是否受限由产品线自行决定，平台不代为承诺。
- **开启 `LICENSE_HARD_ENFORCE=true` 必须提前报备并获平台确认**——硬模式下域名不符/证过期会直接停服，属生产变更。
- 30 天宽限期（`license_since` / `grace_until`）**仅适用心跳体系**，离线证不适用。

### R8 验收闭环：4 项必须原文回传

签发回执给出后，接入方 **3 个工作日内**回传：

1. 启动日志出现 `License OK: tenant=<id> exp=<ts>`；
2. `GET /api/system/license`（或等价接口）`valid=true`，且绑定字段值正确；
3. **既有实例未被误伤**（逐个实例状态）；
4. `sha256sum` 与回执一致。

异常时**回传原始错误串**（`LICENSE_EXPIRED` / `INVALID_SIGNATURE` / `DOMAIN_MISMATCH` / `ISSUER_MISMATCH` 等），**不得改代码绕过**。

### R9 变更通知：换域名/迁移/增减实例，15 天前报备

- 换域名、迁移服务器、拆分/合并实例 → **提前 15 天**报备；紧急变更 24 小时内。
- 含 `domain` 的证在换域名后**立即失效**，须同步申请重签；未报备导致的停服由接入方承担。

### R10 账实不符的处置

出现下列情形，平台**暂停该租户续签、必要时收回/作废现证**，直至对齐：

- 台账缺失或与平台记录不一致且逾期未改；
- 明文凭据出现在 Git/公开渠道；
- 发现借用他租户凭证或绕过校验；
- 到期未续仍对外声称在授权期内。

---

### R11 事实以服务器为准：描述"现状"必须附实测输出

- 申请与回执中凡涉及实例现状（域名、环境变量、版本、目录、权限、进程状态），**必须贴实测命令及输出**；**不得写"将会/计划/已由某方补上"** 这类未验证表述。
- 2026-10-19 实证偏差：①申请称"xgn 侧会在 systemd unit 补 `INSTANCE_DOMAIN`"，实际部署时早已配好且在生效；②申请称 ECMS"实例不联网、不回拨"，实际是公网可达子域。
- 用"文档里的计划"代替"机器上的事实"，会让双方基于错误前提排期。**平台侧同样受此条约束**（回执里的每条现状也要有实测依据）。

## 3. 术语表

| 术语 | 定义 |
|---|---|
| `private` | 一客户一独立实例（独立目录+独立库），**允许托管于我方 CVM**；不等于客户机房 |
| `saas` | 共享实例，走身份 JWT，不发离线证 |
| 软模式 | 校验失败仅 `valid=false` + 日志，不阻断业务（ECMS 默认） |
| 硬模式 | 校验失败即停服/拒请求，须双方确认后可开 |
| 离线证 | RS256 JWT 文件，本地用共用 `public.pem` 验签，不联网 |
| 一次性人工签发 | 平台用脚本写入工单表并签名，用于携带白名单外字段或指定 `iat` |

## 6. 受理方铁律（codebuddy 自约束，v1.2）

> 这一节约束的是**我自己**，不是接入方。规则由发放方先守，才有资格要求别人。
> 执行方式：任何 License 相关回复、响应、交付提示词，**默认自带以下七件套，缺一即视为未完成**，不待对方追问。

| # | 必带内容 | 判定标准（自检） |
|---|---|---|
| 1 | **明文交付块** | `license.key` 完整单行明文 + 长度 + sha256 + 指定接收人 + ack 要求。**只给 sha256 不给明文＝未交付**；"回执已推 Git"**不等于**交付完成 |
| 2 | **事实来源** | 凡涉及实例现状（env / 版本 / 目录 / 进程 / 权限 / PyJWT 版本），附**实测命令与输出**；未实测一律写"未核实"，**禁止**把申请文档里的"将会/计划"当事实转述（R11） |
| 3 | **claim 全量表** | 逐项取值；明确是否含 `domain` / `modules` / `max_devices`；白名单外字段标"续期不延续" |
| 4 | **生效前提与红线** | `INSTANCE_DOMAIN` 精确值要求、硬/软模式、`iat` 未来值与 PyJWT 版本风险、借证/改 claim/开硬模式禁令 |
| 5 | **影响面声明** | P0 租户（`ecms-dna`）未受影响的**证据**（`license_key_issued_at` 时间戳、key 长度）；未改代码/schema、未重启服务 |
| 6 | **留痕与闭环** | 回执路径 + commit 号 + `STATUS.md` 台账行 + 到期日 + 续期方式（含 domain 必须人工重签） |
| 7 | **可转发执行单** | 一段可直接粘给接入方的文本，含 ack 格式、验收 4 项、回报模板、禁止项 |

**三条硬禁**：

1. **禁止**只发 sha256 或"已推送仓库"就结束——这是 2026-10-19 事故的直接成因；
2. **禁止**用"我以为发了"替代 ack——无 ack 即未送达，未送达即未完成，不计入已发放；
3. **禁止**在回复里省略红线段（尤其续期丢 domain、iat/PyJWT、软模式不等于防护三条），哪怕本次只问一句小事。

**回执模板**：`requests/_模板-License回执.md`（七段结构与本节一一对应，出回执时直接套用）。
