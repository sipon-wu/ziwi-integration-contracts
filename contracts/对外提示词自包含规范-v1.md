# 对外提示词自包含规范 v1.0

> 制定方：codebuddy
> 生效：2026-10-19（即日执行）
> 适用：**所有对外提供的提示词/执行单/回执/交付说明**——License 发放、心跳与契约对接、数据下发、部署执行单、schema 变更通知、跨组排期、问题排查指引等，不限于 License。
> 与协同仓的关系：协同仓文件是**正本**，对外提示词是**某一时刻的快照**。快照必须自带 `生成于 commit X`，且**允许并鼓励与正本重复**。

---

## 0. 一条原则

**对外提示词必须自包含（self-contained）：接收方只拿到这一段，就能完整执行。**

不要求对方"先去读协同仓的某节"。宁可重复几百字，不可断链一次。

**为什么（实证）**：2026-10-19 ecms-xgn 签发完成，回执与规则都推到了 Git，但提示词里没有明文、没写"谁把明文送到"，接收方在"准备工作"上停了数小时。重复一段明文的成本是 1 分钟，断链的成本是半天空转 + 双方互疑。

---

## 1. 九段结构（可裁剪，但"执行所需"的段不得缺）

| # | 段 | 要求 |
|---|---|---|
| 1 | **任务与期限** | 一句话说清要对方做什么、什么时候完成、什么是"做完了" |
| 2 | **权威来源** | 文件路径 + commit + 生效日期；**只作延伸阅读，不得作为执行前置**（不得出现"详见…后自行理解"） |
| 3 | **参数快照** | 所有键值**抄进提示词**，不写"见上表/见附件/同上次" |
| 4 | **操作步骤** | 可复制的命令/配置，含工作目录、权限、回滚方式 |
| 5 | **事实与前提** | 分两栏：**已核实**（附实测输出）／**未核实**（显式标注），禁止把"计划"写成"现状" |
| 6 | **约束与红线** | 禁止项 + 违反后果，逐条可判 |
| 7 | **验收与回报格式** | 逐条验收项 + 填表模板，要求**贴原始输出**而非结论 |
| 8 | **确认（ack）** | 时限 + 格式（如"2 小时内回：已收到，长度 N，sha256 前 8 位 X"） |
| 9 | **异常与例外** | 出问题找谁、怎么回传、**不得自行绕过**的明确表述 |

## 2. 反模式清单（出现即返工）

1. "详见 `xxx.md`" / "参见上次的说明" —— 把阅读成本转嫁给对方；
2. 只给哈希不给内容 / 只给链接不给正文；
3. 把申请文档里的"将会/计划"当事实转述；
4. 省略禁止项，认为"对方应该知道"；
5. 期望对方自己推导回报格式；
6. 版本漂移：正本已改，提示词仍按旧版发（必须带 commit，发前核对）；
7. 用"我以为发了"替代 ack（**无 ack 即未送达**）。

## 3. 与协同仓的同步规则

- 正本变更 → 已在途的提示词**不回改**，但**下一次发送必须按最新版重生**；
- 每份对外提示词末尾标注：`生成于 {repo} @ {commit} · {YYYY-MM-DD}`；
- 若提示词与正本冲突，**以提示词内参数快照为准**（因为那是当时双方确认的执行值），但须当日回写正本修正；
- 允许提示词内重复正本条款，视为**有意冗余**，不做"去重优化"。

## 4. 自检清单（发送前 30 秒）

- [ ] 对方只看这一段，能否直接开工？
- [ ] 所有参数是否都在正文里（不是"见某处"）？
- [ ] "已核实/未核实"是否分清？
- [ ] 红线与后果是否写明？
- [ ] 验收项与回报模板是否可直接复制？
- [ ] ack 时限与格式是否有？
- [ ] 是否带 commit 与日期？
- [ ] 异常处理路径是否明确，且禁止自行绕过？
